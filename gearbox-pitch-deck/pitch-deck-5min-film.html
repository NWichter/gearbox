[4:00, 20 s] Gearbox is reliable, and it scales. Reliability: every evidence frame, 77 of 77, matches the original pcaps. A second parser without tshark reads them again. Gearbox measures the clock of each sensor. It reads only headers. The analysis runs in its own process, so the dashboard stays up, and 81 tests run before each push. Scalability, measured on Tesla's captures: in stream mode the alerts come after 4 to 67 seconds, with the same incidents as the batch run. We replayed the captures as 1,000 sensors on 8 workers, and each incident was found. With the beacons summarised on the sensor, one worker handles about 650 sensors, so a site with 2,000 sensors needs 4 workers. More sensors means more partitions, not new code.

[4:20, 15 s] We also found the easter eggs. The name of the lab is in the FT key-holder IDs: airframe.lab. Your APs write Unix time into the beacon timestamp. Real APs count from boot. We use it: we put eight sensor clocks on one clock and measure the drift you planted, to the ppm, 7 of 7. That is also how we see controller stalls: the beacons on all eight channels are late at the same time. If they ask "and with a real TSF?": then Gearbox aligns the clocks with beacon sequence numbers, which is built as a fallback, or with PTP or GPS on the sensors.
